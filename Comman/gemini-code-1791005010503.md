# Backend API Prompt (Node.js + Express.js)

Act as a Principal Backend Engineer. Build a secure, scalable RESTful API service using Node.js and Express.js for a Multi-Vendor Computer Hardware E-Commerce Marketplace.

## 1. Tech Stack & Environment
- **Runtime & Framework:** Node.js with Express.js
- **Authentication:** JWT (JSON Web Tokens) with refresh/access token strategy & `bcryptjs`
- **Database Connector:** MySQL (`mysql2/promise` pool) or Prisma ORM with MySQL
- **Validation & Security:** `zod` or `joi`, `helmet`, `cors`, `express-rate-limit`

## 2. Architecture & Middlewares
1. **Role-Based Access Control (RBAC):**
   - `verifyToken`: Extracts Bearer token, validates JWT, attaches `req.user`.
   - `requireRole(['buyer', 'seller', 'admin'])`: Restricts endpoint access strictly by user role.
2. **Error Handling:**
   - Centralized error handler returning standardized JSON: `{ success: false, message: string }`.

## 3. RESTful API Routes Required

### Authentication (`/api/auth`)
- `POST /register`: Registers User (`buyer` or `seller`), hashes password with bcrypt.
- `POST /login`: Validates credentials, issues JWT containing `{ id, email, role }`.
- `GET /me`: Returns authenticated user profile.

### Buyer & Orders (`/api/orders`)
- `POST /`: Atomic checkout endpoint using SQL Transactions:
  - Verifies current hardware stock.
  - Inserts into `orders` and `order_items`.
  - Atomically decrements product `stock_quantity`.
- `GET /my-orders`: Retrieves buyer's order history with calculated total spent.

### Products & Marketplace (`/api/products`)
- `GET /`: Filter by `category_id`, hardware specs (JSON search), price range, search query, and pagination.
- `GET /:id`: Retrieves hardware details with seller store info.

### Seller Management (`/api/seller`)
- `POST /shop`: Create vendor shop profile (Requires `seller` role).
- `POST /products`: Add new hardware item with JSON technical specifications.
- `PUT /products/:id`: Update price, details, or stock quantity.
- `DELETE /products/:id`: Remove hardware item.
- `GET /dashboard`: Aggregates vendor stats:
  - Total revenue from paid orders (`SUM(price_each * quantity)`).
  - Current low stock count (`stock_quantity < 5`).
  - List of customers who bought from this vendor's shop.

### Admin Management (`/api/admin`)
- `GET /analytics`: DAU, page views, and total user registrations.
- `GET /financials`: Total platform volume, commissions, and system operational costs.
- `PUT /shops/:id/approve`: Approve or reject pending vendor shop applications.

## 4. Output Requirements
- Write clean Express controllers and modular routers (`express.Router()`).
- Include SQL transaction handling for orders to avoid inventory race conditions.
